## Opt-in workflow defect

`.github/workflows/mcp-authorization-e2e.yml` at HEAD contains:

```bash
docker pull "" >/dev/null
```

under `set -euo pipefail`, which fails before dind starts. The cleanup step also
uses plain `docker` commands after the nested `DOCKER_HOST` has been exported,
so it queries the inner daemon instead of the host daemon holding the outer dind
container.

## GitHub workflow registration

The opt-in workflow is not registered in the repository's GitHub Actions
workflow list. The file exists on `develop`; the repository default branch is
`main`, and `main` does not contain this workflow. `workflow_dispatch` therefore
cannot be triggered from the current branch until the reviewed workflow is
present on the default branch or the repository configuration/default-branch
decision is changed by the maintainer.

This is recorded as an explicit PENDING gate, not as a passing run.
